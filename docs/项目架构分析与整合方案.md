# 🔍 项目架构分析与整合方案

## 📊 当前系统架构分析

### 发现的主要问题

#### 1. 图片生成系统严重冗余（3套系统！）

```
系统1: image_modules（图片生成页面）
├─ ImageGeneratorMixin          # 通用图片生成
├─ CharacterPhotoMixin          # 人物照片生成  
├─ ShotManagerMixin             # 分镜管理
└─ 独立的UI界面

系统2: director_modules/SceneImageGeneratorMixin
├─ _call_image_api()            # 调用图片API
├─ _build_shot_image_prompt()   # 构建提示词
└─ 用于导演页面的分镜图片生成（旧系统，功能弱）

系统3: director_modules/SDConsistencyMixin  
├─ SDConsistencyGenerator       # SD一致性生成器
├─ _generate_shot_with_sd_consistency()
├─ 支持人物参考图
└─ 用于导演页面（新系统，功能强）

系统4: director_modules/ConsistencyDialog
└─ _on_generate_portraits()     # 生成人物形象
```

**问题**：
- ❌ 系统2和系统3功能重复，都在导演页面生成分镜图片
- ❌ 系统1的人物生成和系统4的人物形象生成重复
- ❌ 用户不知道该用哪个
- ❌ 代码维护困难

#### 2. 工作流程不清晰

当前实际流程混乱：
```
故事页面 → 生成故事
    ↓
图片页面 → 提取人物 → 生成人物照片？
    ↓
导演页面 → 生成脚本 → 生成分镜 → 生成图片（用哪套系统？）
    ↓
    → 一致性设定 → 生成人物形象？（又重复了）
```

## ✨ 整合方案

### 核心原则
1. **一个功能只保留一个实现**
2. **清晰的线性工作流程**
3. **所有图片生成统一使用SD一致性系统**
4. **人物管理统一到导演页面**

## 🎯 整合后的清晰工作流

```
第1步: 故事页面
   └─ 输入主题 → 生成故事

第2步: 导演页面 - 脚本
   └─ 故事 → AI改编 → 视频脚本

第3步: 导演页面 - 人物管理
   ├─ 智能识别人物
   ├─ 填写人物信息
   ├─ 生成标准形象
   ├─ 生成表情库（7种）
   └─ 生成角度库（3种）

第4步: 导演页面 - 分镜
   └─ 脚本 + 人物 → AI生成分镜列表

第5步: 导演页面 - 图片生成
   ├─ 使用SD一致性系统
   ├─ 自动选择人物表情
   ├─ 保持人物一致性
   └─ 生成所有分镜图片

第6步: 导演页面 - 视频提示词
   ├─ 分析分镜图片
   ├─ 生成即梦AI提示词
   ├─ 添加转场建议
   └─ 导出提示词文件

第7步: 即梦AI网页
   ├─ 上传分镜图片
   ├─ 输入提示词
   └─ 生成视频片段

第8步: 视频剪辑
   └─ 合成完整视频
```
